# DevurityWeb — Claude Project Context

DevurityWeb is the official web platform for Semillero de Investigación Devurity at Universidad Surcolombiana (Colombia). It started as an informational page and evolved into a full operational platform: membership management, QR-based attendance tracking, project visibility, CMS, and RBAC. It also serves as a formal graduation thesis (modalidad de grado) for the core team. Production since March 2026 (v1.1.0-beta).

See `AGENTS.md` for the full agent guide. This file provides Claude-specific context and additions.

---

## Tech Stack

Next.js 15 App Router, React 19, TypeScript strict mode, Tailwind CSS v4, Prisma ORM 6, PostgreSQL (Supabase), JWT + CSRF + RBAC auth, Framer Motion, Vercel (region `gru1`). Package manager: pnpm with pinned versions and frozen lockfile.

## Critical Rules

### BigInt serialization
Prisma uses `BigInt` IDs. JSON cannot serialize BigInt. Always convert with `.toString()` before returning from route handlers or repositories. Missing this causes silent runtime crashes.

```ts
// correct
return { id: user.id.toString(), ... }

// wrong — will crash at JSON.stringify
return { id: user.id, ... }
```

### bcrypt vs bcryptjs
Use `bcryptjs` (pure JS) — `bcrypt` (native C++ addon) is incompatible with Vercel Edge Runtime. The import is in `lib/bcrypt.ts` — do not change it.

### Edge Runtime constraints
`middleware.ts` runs on Edge V8 isolates. It cannot: use Node.js built-ins, import `lib/email.ts`, `lib/jwt.ts` (use `lib/auth/jwt-edge.ts` instead), or make self-referential `fetch()` calls. JWT verification in middleware uses `crypto.subtle` HS256 via `verifyJwtPayload()`.

### App Router boundaries
`"use client"` only when hooks, browser APIs, or client state are strictly required. Server-only code — DB queries, JWT verification, `lib/email.ts`, `lib/bcrypt.ts` — must never leak into client components. Prefer Server Components by default.

### Prisma singleton
`lib/postgresDriver.ts` exports a single `PrismaClient` bound to `globalThis`. Never instantiate `PrismaClient` elsewhere. Hot-reload in dev and serverless cold starts both depend on this singleton.

### ISR patterns
Public content pages use `revalidate = 21600` (6 hours). The admin dashboard uses `force-dynamic` — every request fetches fresh data. The landing page `app/page.tsx` uses `force-dynamic` after a production prerender failure was discovered post-deploy.

### Framer Motion
Use `LazyMotion` with `domAnimation` features for all animations. Do not import full `motion` directly — it significantly inflates the bundle. The centralized setup is in the layout.

## Auth and Security

### CSRF
Every `POST`, `PUT`, `PATCH`, `DELETE` must carry `x-csrf-token` header matching the `csrf_token` cookie. Client-side: use `fetchWithCsrf()` from `hooks/useCsrf.ts`. Server-side validation runs in `middleware.ts`. Public exemptions (login, register, logout, refresh, forgot/reset password, qr-dinamico, asistencia, admin/attendances) are hardcoded in `middleware.ts` — adding new public mutation routes requires updating that list explicitly.

### JWT tokens
Two JWT implementations exist for a reason. `lib/jwt.ts` uses `jsonwebtoken` — Node.js only, for route handlers. `lib/auth/jwt-edge.ts` uses `crypto.subtle` HS256 — Edge-compatible, for middleware. Never use the Node.js version in middleware.

### RBAC
Four roles: `admin`, `content_manager`, `project_lead`, `user`. The role claim lives in the JWT payload and is verified by `verifyJwtPayload()` in middleware. Role changes propagate on the next token refresh without re-login. Route access matrix:

| Route | admin | content_manager | project_lead | user |
|---|:---:|:---:|:---:|:---:|
| `/admin/updates/*` | ✅ | ✅ | ❌ | ❌ |
| `/admin/gallery/*` | ✅ | ✅ | ❌ | ❌ |
| `/admin/projects/*` | ✅ | ❌ | ✅ | ❌ |
| `/admin/users/*` | ✅ | ❌ | ❌ | ❌ |

### Rate limiting
Login endpoint uses in-memory `Map` — resets on server restart and does not work across Vercel serverless instances. This is known technical debt; do not add more in-memory rate limiting.

## Prisma Rules

> Never run Prisma commands that modify schema or data without explicit user confirmation. State what you intend to do and wait for approval.

**Workflow for schema changes:**
1. Edit `prisma/schema.prisma`
2. Tell the user to run: `npx prisma migrate dev --name <description>`
3. Verify migration SQL in `prisma/migrations/`
4. Run `npx prisma generate` to update the client
5. Never edit `lib/generated/prisma/` — regenerated on every `prisma generate`

**BigInt ID convention:**
All PKs and FKs are `BigInt`. Route params arrive as `string` — always convert with `BigInt(param)` or the `toBigInt()` helper before passing to Prisma. Return values must convert with `.toString()` before leaving the server.

**Junction tables with `onDelete: NoAction`:**
`user_platforms` and `user_projects` require manual cascade in repository transactions — delete junction rows before deleting the parent.

## Manual Actions — Do Not Execute

Never run these. Output a `MANUAL ACTION REQUIRED` block describing what the user should run:

- `npx prisma migrate dev` / `deploy` / `db push`
- `pnpm db:seed` / `db:repair`
- Editing `.env`, `.env.local`, `.env.example`
- Editing `middleware.ts` CSRF public paths
- Editing `lib/jwt.ts` or `lib/auth/jwt-edge.ts`
- Editing `lib/csrf.ts`
- Git push, merge, or deploy
- Editing `lib/generated/prisma/`
- Installing new dependencies with `pnpm install`

Format for manual action blocks:
```
MANUAL ACTION REQUIRED:
1. Run: npx prisma migrate dev --name add_user_bio
2. Verify the generated SQL in prisma/migrations/
3. Confirm before I continue
```
